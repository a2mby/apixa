# v3.0.0 — Scope

## In scope

| Area                  | Work                                                                                                                                                                                                                                                                                                                                                       |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Correctness           | Fix slice overflow, reject slice with pagination, reject invalid collection shapes and apply middleware query mutations consistently.                                                                                                                                                                                                                      |
| Definitions and calls | One operation selector and declaration model; derive HTTP kinds; positional `(id, body, options?)` detail writes; unified middleware syntax (including `onAttempt` / `onAttemptResponse`); consistent typed call options; typed identity, `getMany` batch contract, and `count` normalization; remove redundant builtins and deprecated aliases (ADR-007). |
| Requests              | Structured queries and configurable empty values, client-wide query formats, correct encoding, raw and JSON strings, safe body serialization, structured `timeout: { total, perAttempt }`, `retry` backoff/jitter, and typed errors.                                                                                                                       |
| Responses             | Strict JSON and explicit automatic parsing, inherited unwrapping, builtin structural contracts, generic validation hooks, `onResponse` before `schema.response`, `emptyResponse`, bounded/excluded key transforms, and parsed source preservation.                                                                                                         |
| Pagination            | Strict `paginationConfig` (resource) vs `pagination` (operation) vs `options.pagination` (call), consistent preset expansion and common live/mock contracts; slice remains client-side.                                                                                                                                                                    |
| Integrations          | Migrate Core, Mocking, React, the public facade, maintained Next example and packed consumers; retain advanced transfers and optional integrations.                                                                                                                                                                                                        |
| Schemas (ADR-006/007) | Per-operation Standard Schema V1 `schema`, `emptyResponse`, flat `ApiState`, `SchemaValidationError`, and the optional `apixa/validation` subpath backed by the private workspace `@apixa/validation` (added by owner request).                                                                                                                            |
| Release preparation   | Documentation, v2-to-v3 migration guide, changelog, release metadata, regression/type/real HTTP checks, full verification and Node 22/24 CI.                                                                                                                                                                                                               |

## Out of scope

| Area                                            | Reason                                                                                                                                                                   |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| npm publication                                 | The owner requested a verified release candidate, not publication.                                                                                                       |
| New framework or transport packages             | Preserve existing package boundaries and framework-independent Core.                                                                                                     |
| Required schema library                         | Standard Schema V1 `schema` is in scope (ADR-006); the optional `apixa/validation` (Zod) subpath was added by owner request. No schema library is a required dependency. |
| Unrelated examples or backend changes           | Keep the maintained Next consumer and backend behavior intact.                                                                                                           |
| Hidden compatibility layers and backend guesses | v3 is a coordinated breaking release with explicit conventions.                                                                                                          |
